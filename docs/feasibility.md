# 方案可行性核查

核查日期：2026-11-18。依据 HIFE-YOLO 出版正文、Tables 2–6 和 Data Availability Statement，以及定向公开代码检索。

## 判断

**路线可行，值得执行；HIFE-YOLO 的精确复现有未解决前提，超过它仍须实验确认。**

可行依据：

- 原版是约 2.6M 参数的 YOLO11n；论文结构由卷积、池化、门控与残差构成，适合单 GPU 实验，不依赖额外模态或大模型预训练。
- 原文使用 8 GiB RTX 3070，主要协议为 640 / batch 8 / 100 epochs，说明存在单卡执行先例。不同 GPU 和软件栈的实际显存、时长仍须短任务测量。
- 结构插入点、组件说明、训练配置、配对 seed 与消融可作为独立实现依据。
- 相比原版的提升幅度适合以稳定改进和有效证据为目标；不能据此估计新方法一定涨点或保证录用。

## 复现关卡

先投入一个短实现周期（目标 1–2 个工作日，非训练时长承诺）：

1. 取得论文完整结构与配置，整理仍未确定的细节。
2. 完成模块维度、前向／反向、共享张量初始化检查；验证 CTD 零初始化条件下的恒等性质。
3. 在同一融合与计算统计口径下，核对论文参数量和 GFLOPs；不匹配时先解释原因。
4. 验证数据清单、类别、空标签、坏图及训练／验证／测试分离。
5. 在云上完成短训练、断点恢复和重评测，才提交完整任务。

若不能得到足以辨识论文方法的实现，或关键细节始终缺失，就重新评估主对标对象；不在不确定重建模型上投入大规模训练。

## 怎样定义“超过”

- 核心比较：新模型与论文重建模型在相同数据、训练预算、初始化规则及模型选择流程下比较，原版 YOLO11n 同时保留。
- 主精度指标：mAP50–95；同时报告 mAP50 和 fire/smoke AP50。提升一个指标不代表全面超过。
- 最终确认：三个配对训练 seed，报告逐 seed 与均值／标准差；交代计算、参数、速度与类别之间的代价。
- 推荐研发目标：验证集上争取约 1 个百分点或更有实际意义的改进，并尽量减少资源代价。此为筛选目标，不是录用门槛或统计显著性保证。
- 调参与候选筛选使用验证集。最终结构冻结后才批量运行预定测试，不能用测试集反复筛选模块。
- 不直接用新协议数字减去文献成绩宣称战胜 SOTA；本次检索没有建立统一 SOTA 排行榜。

## 结论对执行的影响

立即从新项目开始。先完成原版与对标模型各一次完整训练，确认流程合理后进入改进，不等全部重复实验结束。最终候选确定后再用连续算力补齐多 seed 和最终矩阵。
