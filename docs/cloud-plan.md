# 云端训练安排

## 平台分工

| 平台 | 任务 | 约束 |
|---|---|---|
| 本地 | 代码、文档、日志和图表 | 不承担长期 CPU 训练 |
| Google Colab | 首次环境闭环、基线和候选 | GPU 型号、配额、连续时长依实际账号与可用性变化 |
| Kaggle | 数据挂载、基线和候选 | 受实际 GPU 配额、会话时长、联网条件约束 |
| 租用 RTX 4090 | 最终多 seed、消融、对比及统一测速 | 以实测资源和总预算决定，不在本阶段购买或启动实例 |

原文单卡 8 GiB RTX 3070 提供硬件可行依据，但不等于当前任意免费会话都能完成 100 epochs。

## 统一执行规则

- 同一 Git commit、模型配置、数据清单与训练协议跨平台运行。
- 原文软件栈见 configs/hife-paper-protocol.yaml；先验证安装与模块兼容，再建立可执行依赖锁定。
- 尽量在同一软硬件环境完成最终配对 seed；跨硬件变化必须登记。
- 训练本地磁盘存取，按可接受丢失进度定期同步持久存储，避免将每个 batch 的 I/O 指向云盘。
- 至少保存 best、可恢复 last、逐 epoch 日志、配置与环境记录。检查恢复是否保留优化器、调度器、AMP 状态、epoch 及随机状态，并记录框架实际保证的范围。
- 中断优先恢复同一 run；不能精确恢复时标明差异，不覆盖历史记录。
- 三个平台都使用正式数据准备入口，不在 Notebook 内自行随机重划分。
- 数据、权重、缓存、训练输出和凭据不进 Git。

## 计算预算

完成 R00 后记录实际 epoch 时长、峰值显存、检查点同步开销及完整任务耗时，再按计划运行数估算剩余 GPU 小时。最终矩阵包含原版、论文对标、最终方案各三个 seed；先前有效运行可计入，消融和额外方法另计。

4090 单价、可用时段和存储费用确定后再估算总费用。换更快 GPU 只能缩短迭代，不代替数据、初始化和评测口径的一致性。

## 首次云任务验收

1. 从干净环境装依赖，加载模型和固定数据清单。
2. 验证类号、图像读取、标签坐标和背景图。
3. 短训练能输出日志、best 与 last。
4. 从 last 恢复，确认训练进度和关键状态。
5. 重新评测保存的权重，记录原始指标。
6. 验证输出已到持久存储，才开始完整训练。
